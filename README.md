# 과제 07: 인접 행렬과 인접 리스트의 성능 비교

## 1. 파일 구성

- `main.c`: 그래프 생성, 두 표현의 연산, 비교 횟수 측정, 메모리 계산 및 결과 검증.
- `sample_output.txt`: seed 1의 실제 실행 결과.

## 2. 구현 및 실험 방법

정점은 0~99이고, 가능한 정점 쌍 `u<v`를 모두 나열하면 4,950개이다. 이 배열을 셔플한 후 앞의 100개 또는 4,000개를 간선으로 선택했다. 따라서 자기 루프와 중복 간선이 생기지 않는다. 같은 간선 목록으로 행렬과 연결 리스트를 구성했다. 무방향 간선은 행렬의 두 칸과 리스트의 두 노드에 각각 저장했다.

각 그래프에서 없는 간선 하나, 기존 간선 하나, 연결 확인용 서로 다른 두 정점, 인접 정점 출력용 정점을 선택했다. 두 표현에 같은 대상을 적용하고, **삽입 → 삭제 → 연결 확인 → 인접 정점 출력** 순서로 연산했다. 삽입할 간선과 삭제할 간선은 서로 다르다. 삽입과 삭제 후 간선 수는 원래 E와 같다.

`check()`는 행렬의 0/1 값, 대칭성, 자기 루프 부재, 리스트 정점 범위, 중복 부재, 두 표현의 모든 인접 정점 일치 및 전체 리스트 노드 수 2E를 검증한다. 생성 후와 연산 후에 검증하며, 검증 자체는 비교 횟수에 포함하지 않는다. 출력된 인접 정점도 집합이 같은지 확인한다. 행렬과 리스트의 출력 순서는 다를 수 있다.

## 3. 비교 횟수 및 메모리 기준

비교 횟수는 그래프 자료구조의 원소 또는 간선 정보를 실제로 확인한 횟수이다. 반복문 조건, 포인터의 NULL 검사, 값 쓰기, 난수 생성, 검증 및 화면 출력은 포함하지 않는다.

| 연산 | 인접 행렬 | 인접 리스트 |
|---|---|---|
| 삽입 | 없는지 한 칸 확인: 1회 | u의 리스트 전체를 확인: 삽입 전 deg(u)회. 맨 앞 삽입은 위치 탐색 없음 |
| 삭제 | 있는지 한 칸 확인: 1회 | 양쪽 리스트에서 상대 정점을 찾을 때까지 확인한 노드 수의 합 |
| 연결 확인 | 한 칸 확인: 1회 | 찾을 때까지 확인. 없으면 현재 deg(u)회 |
| 인접 정점 출력 | 행 전체 확인: 100회 | 현재 deg(u)회 |

무방향 그래프의 대칭성을 유지하므로 삽입 시 중복 여부는 한쪽 리스트에서 확인하면 충분하다. 빈 리스트는 확인한 노드가 없으므로 0회이다. 삭제는 양쪽 노드를 실제로 찾아야 하므로 두 탐색을 합산했다.

메모리는 행렬 전체 또는 리스트의 헤드 배열과 2E개 노드의 `sizeof` 합으로 계산했다. 결과 기록 구조체, 임시 간선 배열, 검증 배열 및 프로그램 코드는 그래프 표현용 메모리에서 제외했다. 별도 그래프 관리 구조체는 사용하지 않았다. `sizeof(Node)`는 정렬 패딩을 포함하지만 `malloc` 내부 관리 공간은 포함하지 않는다.

- 행렬: `sizeof(int[100][100])` = 40,000 B.
- 리스트: `sizeof(Node *[100]) + 2E * sizeof(Node)` = 800 + 32E B.

## 4. 실행 결과

| 메모리 (Byte) | 40,000 | 4,000 | 40,000 | 128,800 |
| 삽입 비교 | 1 | 1 | 1 | 77 |
| 삭제 비교 | 1 | 2 | 1 | 58 |
| 연결 확인 비교 | 1 | 5 | 1 | 56 |

Sparse: 삽입 (30,85), 삭제 (31,71), 연결 확인 (86,85)는 연결 없음, 인접 정점 출력은 정점 80이다.

Dense: 삽입 (55,92), 삭제 (25,39), 연결 확인 (88,9)는 연결 있음, 인접 정점 출력은 정점 65이다. 실제 인접 정점 목록은 `sample_output.txt`에 포함했다.

### seed 1~1000의 실제 평균

각 seed에서 두 그래프를 새로 생성하고, 각 그래프에 연산별 한 번씩 측정했다. 따라서 그래프 종류별로 각 연산의 표본은 1,000개이며, 같은 그래프에서 1,000번 연산한 결과는 아니다.

| 평균 비교 횟수 | Sparse 행렬 | Sparse 리스트 | Dense 행렬 | Dense 리스트 |
|---|---:|---:|---:|---:|
| 삽입 | 1.000 | 1.992 | 1.000 | 79.221 |
| 삭제 | 1.000 | 3.994 | 1.000 | 79.897 |
| 연결 확인 | 1.000 | 2.050 | 1.000 | 46.761 |
| 인접 정점 | 100.000 | 2.077 | 100.000 | 79.894 |

메모리는 V와 E가 고정되어 모든 seed에서 위 표와 같았다. 전체 측정값은 `measurements.csv`에 저장했다.

## 5. 희소 그래프 분석

V=100, E=100이면 평균 차수는 2E/V=2이고 밀도는 100/4950 ≈ 2.02%이다. 리스트는 헤드 배열과 200개 노드만 저장하여 4,000 B를 사용했다. 이는 행렬 40,000 B의 1/10이다. 행렬은 간선이 없어도 10,000칸을 모두 저장해야 한다.

단일 실행에서 리스트의 삽입·삭제·연결 확인 비교 횟수는 1, 2, 5회였다. 반복 실험에서는 각각 약 1.99, 3.99, 2.05회로 나타났다. 행렬은 모두 1회로 더 적지만, 이 그래프에서는 리스트의 탐색 길이도 짧았다. 특히 인접 정점 출력은 행렬 100회에 비해 리스트 평균 약 2.08회로 확인할 원소 수가 크게 줄었다. 따라서 희소 그래프에서 리스트는 메모리와 이웃 순회에 유리했다.

## 6. 밀집 그래프 분석

V=100, E=4000이면 평균 차수는 80이고 밀도는 4000/4950 ≈ 80.81%이다. 행렬은 40,000 B 그대로였지만 리스트는 8,000개 노드를 저장하여 128,800 B를 사용했다. 이 구현에서 리스트는 행렬보다 3.22배의 메모리를 사용했다. 각 노드의 포인터와 정렬 패딩이 공간을 늘렸다.

행렬의 삽입·삭제·연결 확인은 계속 1회였다. 리스트는 평균 약 79.22, 79.90, 46.76회로 증가했다. 없는 간선 삽입은 한쪽 리스트 전체를 확인해야 한다. 기존 간선 삭제는 양쪽 리스트를 탐색하며 선택한 간선의 위치에 따라 횟수가 달라진다. 연결 확인은 간선이 있으면 발견 즉시 종료하고, 없으면 전체를 확인하므로 삽입보다 평균 횟수가 작았다.

인접 정점 출력은 행렬 100회, 리스트 평균 약 79.89회로 차이가 줄었다. 이웃이 많아져 리스트에서도 많은 노드를 방문하기 때문이다. 다만 배열 접근과 연결 리스트 순회는 메모리 접근 방식이 다르므로 비교 횟수가 비슷하다고 실제 실행 시간까지 같다고 결론 내릴 수는 없다.

## 7. 표현 방법의 선택 및 한계

희소 그래프, 정점이 많아 V² 저장이 부담되는 그래프, BFS/DFS처럼 이웃 순회가 많은 연산에는 인접 리스트가 적절하다. 리스트에서 전체 이웃을 순회하는 비용은 O(V+E)이다. 이 코드의 중복 확인을 포함한 삽입은 O(deg(u)), 삭제는 O(deg(u)+deg(v)), 연결 확인은 O(deg(u))이다. 중복 확인이 필요 없다면 리스트의 맨 앞 삽입 자체는 O(1)이다.

밀집 그래프, 연결 여부를 자주 확인하는 경우, 간선 삽입·삭제가 많은 경우에는 인접 행렬이 적절하다. 이 코드에서 세 연산은 O(1), 한 정점의 이웃 출력은 O(V)이다. 행렬 방식의 전체 BFS/DFS는 일반적으로 O(V²)이다.

현재 자료형 크기에서 메모리가 같아지는 조건은 40,000=800+32E이므로 E=1,225, 밀도 약 24.75%이다. 그보다 간선이 많으면 행렬의 계산된 저장 공간이 더 작다. 이는 이 구현의 기준이며 모든 인접 리스트에 적용되는 고정 임계값은 아니다. 예를 들어 행렬을 1 B 원소로 저장하면 10,000 B가 되어 E=287.5에서 같아지고, 정수 간선 수 기준 288개부터 행렬이 더 작아진다.

실험은 원소 확인 횟수와 sizeof 기반 저장 공간을 측정했다. 실행 시간, 캐시 효과, 메모리 할당·해제 시간과 malloc 내부 공간은 측정하지 않았다. 단일 실행은 정점 선택에 따른 편차가 있으므로 반복 실험 평균도 함께 제시했다. 난수 생성은 rand()와 나머지 연산을 사용하므로 엄밀한 균등 분포를 보장하지는 않는다.

검증 시 엄격한 경고 옵션으로 컴파일하고, seed 1~1000에서 그래프 및 결과 검증을 통과했다. AddressSanitizer/UndefinedBehaviorSanitizer로 seed 0, 1, 3, 7, 42, 2026, 4294967295를 검사하여 오류가 없었다. 실행 환경의 제한으로 sanitizer의 누수 검사는 비활성화했으며, 정상 종료 시 모든 리스트 노드를 free하도록 구현했다.
